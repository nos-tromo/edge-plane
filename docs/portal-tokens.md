# Portal design tokens

The build-free portal pages (`landing/index.html`, `authcode/index.html`)
link a vendored copy of `@infra/ui`'s plain-CSS design tokens,
`landing/tokens.css` — the same background/foreground/muted/border/primary/
danger custom properties the React frontends get via Tailwind, plus its
dimensional scale (`--text-xs/sm/base/lg/xl/2xl`, `--radius-md/lg`),
exported as plain `:root` rules for consumers with no build step. It's
vendored, not
`@import`ed live, following the same pattern as `scripts/bundle-lib.sh`:
`landing/tokens.css`'s header comment records the canonical source
(`nos-tromo/infra-ui`, pinned commit or tag) and the manual re-vendor step; CI
(`scripts/check-tokens-vendor.sh`) only checks that header is present and
well-formed — this repo is airgap-first, so CI never fetches infra-ui over
the network, regardless of whether the pinned ref is a branch commit or a
release tag.

## Re-vendoring

To pull in a newer infra-ui release, regenerate the whole file — header and
body, never by hand — from a checkout of infra-ui at the tag to vendor:

```bash
python3 - vX.Y.Z <SHA> <<'PY'
import pathlib, sys
tag, sha = sys.argv[1], sys.argv[2]
upstream = pathlib.Path('../infra-ui/dist/tokens.css').read_text().lstrip()
header = f"""/* Vendored verbatim from nos-tromo/infra-ui, dist/tokens.css.
 *
 * Canonical source: nos-tromo/infra-ui, tag {tag} (commit {sha})
 *
 * This repo's CI (scripts/check-tokens-vendor.sh) only verifies this header is
 * present and well-formed — it does not fetch infra-ui over the network in CI,
 * the same constraint that keeps scripts/bundle-lib.sh a manually re-vendored,
 * drift-checked-by-header copy rather than a live fetch.
 *
 * Never hand-edit this file, header or body. Re-vendor by following the
 * procedure in this repo's docs/portal-tokens.md, "Re-vendoring" section.
 */

"""
pathlib.Path('landing/tokens.css').write_text(header + upstream)
PY
```

Use the full header above verbatim — a truncated one (e.g. just the
canonical-source line) still satisfies `check-tokens-vendor.sh`, which only
greps for the canonical-source and pinned-ref lines, but it silently drops
the "never hand-edit" instruction and the pointer back to this page that the
real header carries.

Then confirm `./scripts/check-tokens-vendor.sh` passes and that the file is
byte-identical to upstream *from* the `GENERATED by` line onward (that
banner is part of the upstream body, not something this repo adds). Adjust
the path to infra-ui's checkout as needed if it isn't a `../infra-ui`
sibling.

It's served unauthenticated at the absolute path `/tokens.css` (a dedicated
Caddyfile matcher, `root * /srv/landing`) rather than a same-origin relative
link — `authcode`'s handle rewrites every `/auth-code/*` path to
`index.html`, so a relative link scoped under that prefix would never reach
a real file.

Each page still keeps a small local `<style>` block, but the only *color*
custom properties it declares are: aliases that reference the vendored
tokens 1:1 (`--bg`/`--surface`/`--border`/`--text`/`--muted`/`--neutral` —
true duplicates of infra-ui's values, no longer hand-copied) plus a handful
of portal-owned tokens that are genuinely *not* shared with infra-ui:
`--accent` and `--down` use portal-tuned values distinct from
`--color-primary`/`--color-danger` (this unprocessed static HTML needs its
own AA-checked contrast against a plain white/near-black surface), and
`--ok` (the online-status green) has no infra-ui equivalent at all —
infra-ui ships no status-color tokens. Dimensions are not aliased at all:
every `font-size` and `border-radius` declaration in that `<style>` block
references `var(--text-*)`/`var(--radius-*)` directly from the vendored
file.

## Enforcing the dimensional scale

`scripts/check-no-literal-dimensions.sh` (run in CI, see
`.github/workflows/ci.yml`) fails if either portal page's `font-size`, the
`font` shorthand, or any `border-radius` property (shorthand or longhand)
resolves to anything other than one of the eight tokens above, a CSS-wide
keyword (`inherit`/`initial`/`unset`/`revert`/`revert-layer`), or the
`border-radius: 50%` circle exception. It checks membership in that
specific token set, not merely that the value is *some* `var()` call, so a
typo'd or nonexistent token name is caught rather than silently dropping at
computed-value time. See the script's own header comment for the full
rationale and its known limitations.

Spacing (`padding`/`margin`/gaps) was hand-snapped to `@infra/ui`'s
`.25rem` spacing grid in the same pass but is **not** guarded the same way:
`--spacing` is deliberately unexported by infra-ui, so there is no token
set to check membership against — only an arithmetic "is this a multiple of
.25rem" rule, which this check does not attempt. That snap is a one-time
cleanup, not an enforced invariant, and can drift back on a future
hand-edit; `letter-spacing` is similarly unguarded and has no token scale
at all.
